# 节点图事件触发

自定义事件把时间轴中的演出接到你自己的游戏逻辑，例如切换实体状态、生成物件、修改任务条件或记录剧情结果。

视频对应：[16:08 附近](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=968)。常用现成行为请先看[公共事件](../../../public-events/public-events.md)。

## 添加与接收事件

1. 在 Group 的时间轴中添加自定义事件片段。
2. 填写事件名，例如「打开大门」，并设置它在当前 Group 中的开始时间。
3. 在游戏中为相应实体挂载节点图，用「收到自定义事件时」接收事件。
4. 按事件名筛选，只让「打开大门」分支执行开门逻辑。
5. 按[通用步骤](../../../editor.md#try-in-game)更新演出变量，试玩确认门在指定时刻打开。

![游戏节点图接收演出触发的自定义事件](/images/tutorial-v2/custom-event.jpg)

*图：视频 [16:30](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=990)。*

接收事件的实体必须与事件实际发送的对象一致。最小示例可把演出数据和接收节点图放在同一目标实体上，确认可用后再拆分逻辑。

## 事件与流程推进分开设置

触发事件只是执行行为；下一 Group 由出口决定。例如「开门」事件发生在第 1 秒，并不表示演出会在第 1 秒自动结束。

需要等事件完成才继续时，应明确安排等待、后续推进或自己的回调逻辑。事件中的传送、销毁等行为也可能影响当前演出的目标实体，测试时要覆盖这些情况。

## 与旧版的区别

0.1.x 按每句话的零基序号配置事件字典，并使用旧版的对话事件入口。2.x 改为时间轴片段触发自定义事件，不再照搬「第 0 句话／第 N+1 个事件」的设置。

旧文档中 `***对话结束***` 这个特殊事件名也不能当成新版的通用接口。需要收尾逻辑时，在自己的演出时间轴或所用版本提供的接口中明确实现，并验证正常结束和中途退出的情况。
