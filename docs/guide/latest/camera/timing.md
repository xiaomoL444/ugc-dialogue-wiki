# 镜头过渡与触发时序

时间轴上的开始时间决定何时触发，持续时间用在镜头的运动或过渡上。要让镜头先到位再开始说话，可以把台词往后排，试玩时从触发镜头的上一句开始测试。

## 起点与立即抵达

- 机位和视点设为线性移动时，只有终点会使用当前镜头位置或当前视点作为起点。希望每次的镜头一致时，可显式填写起点。
- 机位「跟随」和视点「固定视点位置」可选「是否立即抵达目标」。直接切镜时打开，需要过渡时关闭。可以在[机位线性移动的演示](./position/linear.md#效果演示)里观察机位到达终点前后的变化。
- 演出结束前需要回归普通视角时，可添加公共事件[重置镜头](../public-events/reset-camera.md)。

## 前摇和客户端位置

2.0 视频提到镜头有约 0.03 秒的前摇。2.1 修复教程调整了相关节点图的定时器，修复后的前摇约为 0.12 秒。对照自己地图实际采用的节点图再调整台词、动作和镜头相对时间。见[版本与升级](../upgrade.md#固定位置镜头)

线性移动通常用服务器计算的位置。以客户端运动器驱动的实体作点位时，按模板要求使用「需要客户端位置」。等待客户端回传数据可能增加过渡延迟。经典模式不支持需要获取玩家镜头数据的操作，涉及当前镜头起点时尤其要试玩核对。
