# 存档功能

模板提供一套基础存读档逻辑，用于保存任务、游戏数据状态及部分背包内容。它随**超限模式地图版**提供，需要通过游戏节点图调用。

视频对应：[30:08—31:18](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=1808)。

## 默认范围

| 数据 | 视频所示默认范围 |
| --- | --- |
| 已接取任务及其进度 | 最多 20 个 |
| 游戏数据状态 | 长度为 100 的整数列表 |
| 背包道具 | 最多 20 种 |
| 货币 | 最多 5 种 |
| 存档位 | 4 个 |

这是模板默认实现的范围，不代表千星编辑器的通用上限。改动容量时，需要同步检查数据结构、保存节点和读取节点。

## 使用流程

1. 保留模板已有的存档初始化逻辑。视频中的存档数据会在游戏开始时进行初始化。
2. 在检查点、交互选项或自己的菜单事件中调用模板的存档节点，指定玩家和存档位。
3. 读取时调用读档节点，使用相同的存档位约定。
4. 检查读档后的任务、进度、背包和游戏数据状态是否恢复。
5. 对机关、门、拾取物等自定义实体，按恢复的游戏数据状态重建表现。

## 哪些数据要自己接入

自定义变量或实体状态不会因为使用了模板就全部自动保存。例如门是否打开，应该明确写入[游戏数据状态](./场景管理.md#game-state)，再在读取后应用到门。

同样，演出播放到第几句、临时生成的实体和自定义玩法数据，不能默认视为已经接入。先确定需要恢复的内容，再实现它的保存与还原逻辑。

## 最小验收

用一个任务、一扇门和少量背包内容做测试：

1. 记录初始状态，保存到一个测试存档位。
2. 完成任务、开门并改变背包。
3. 读回测试存档，确认各项恢复到保存时的状态。
4. 再检查不同存档位、任务失败回溯和自定义机关是否互相影响。

「我的奇域」中导入／导出的 GIL 是地图工程存档；本页讨论的是模板在游玩过程中的存读档功能，二者用途不同。
