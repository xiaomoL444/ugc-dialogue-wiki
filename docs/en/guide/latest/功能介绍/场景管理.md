# 场景管理

场景模块用「世界 → 一级区域 → 二级区域」组织地图，任务追踪和区域 BGM 会使用这些信息。这里的世界是模板中的逻辑分区，不等于另一个 `.gil` 地图存档。

该模块随**超限模式地图版**提供。视频对应：[26:06—30:08](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=1566)。

## 1. 配置世界与区域

在网页编辑器选择「场景」，先建立世界，再建立一级区域和二级区域。

| 层级 | 主要内容 | 示例 |
| --- | --- | --- |
| 世界 | 名称、ID、通往其他世界的关联点 | 地面、地下空间 |
| 一级区域 | 名称、ID、所属世界 | 城镇、森林 |
| 二级区域 | 名称、ID、所属一级区域、BGM | 城镇广场、城镇街道 |

保留稳定且不重复的 ID。任务引用一级区域，游戏节点图切换二级区域，不能把不同层级的编号混用。

完成后导出千星场景配置，更新模板场景管理实体的对应变量。模板读取的配置变量为 `NOLOC_场景配置数据`；保留模板原有变量名及读取关系。

## 2. 在游戏中切换二级区域

区域配置不会自动在地图上生成检测范围。需要在游戏中布置碰撞器，或通过自己的节点逻辑调用模板的区域切换节点。

1. 为某个二级区域设置合适的触发范围。
2. 玩家进入时，取得对应玩家，并切换到这个二级区域 ID。
3. 处理边界、重叠和离开范围的情况，防止连续重复切换或保留错误区域。
4. 在相邻区域之间走动，检查名称提示、当前区域和 BGM。

![使用场景中的触发范围划分区域](/images/tutorial-v2/scene-regions.jpg)

*图：视频 [26:36](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=1596)。*

模板也提供区域切换事件，可在玩家进入某个二级区域时触发自定义逻辑。以已有场景示例的节点图为接线参考。

## 3. 世界关联点与任务追踪

任务目标和玩家位于不同世界时，不能只显示到目标坐标的直线距离。世界之间的关联点用于告诉玩家应该先去哪个出入口。

例如玩家位于地面世界，任务在地下世界，就在对应世界配置中建立前往地下的关联点，并把任务的一级区域关联到地下世界。

关联点是任务提示所用的位置数据；实际的传送行为仍要由游戏节点图实现。需要双向往返时，分别检查两个方向的配置。

## 4. 区域 BGM 与演出 BGM

二级区域可以配置 BGM。演出需要指定音乐时，使用[公共事件](./公共事件.md)中的「锁定并播放 BGM」；演出结束后使用「解锁 BGM」，把控制交回区域管理。

如果走进新区域音乐没有变化，先检查是否仍处于演出 BGM 锁定状态，再检查二级区域切换和 BGM 索引。

## 游戏数据状态

场景模块还管理一份游戏数据状态：使用长度为 **100 的整数列表**，通过整数中的二进制位记录门是否打开、物件是否拾取或其他游戏状态。

![网页中的游戏数据状态与二进制预览](/images/tutorial-v2/game-state.jpg)

*图：视频 [29:41](https://www.bilibili.com/video/BV1ZCng6LEKV/?t=1781)。*

例如给一扇门分配某个状态字段：

1. 游戏开始或读档后读取这个字段，决定门的初始状态。
2. 玩家开门时修改字段，同时执行开门表现。
3. 保存时把状态随游戏数据一起写入；读档时按读取值恢复门。

同一个整数中可以分配多个字段，字段的位范围不能重叠。分配后记录用途和数值范围，避免不同机关写到同一位置。

网页提供二进制预览，也支持读取导出的存档 GIA 检查状态。它是查看与校对工具；只修改网页预览，不会直接改变正在运行的游戏。

游戏数据状态不会自动记录每个场景实体的全部属性。需要持久化的机关，必须明确接入状态读取、写入和恢复逻辑。下一步见[存档功能](./存档功能.md)。
